## 개요

Altera DE2 보드와 PS/2 키보드로 조작하는 VGA 두더지 게임을 구현한 학부 팀 프로젝트입니다. 저는 `background`, `mux_mole`, `mux`, `mux_start` 모듈을 담당해 배경·두더지·망치·시작 화면의 생성과 RGB 합성 경로를 구현했습니다. 팀의 키보드 입력·게임 제어 모듈과 연결해 보드에서 동작을 확인했습니다.

## 본인 역할

- `background`, `mux_mole`, `mux`, `mux_start` 모듈 구현
- 화면 좌표에 따라 각 화면 요소를 표시하고 RGB를 단계별로 합성
- 각 모듈이 담당 영역의 RGB를 출력하고 나머지 영역에서는 앞단의 RGB를 전달하도록 구성

## 화면 생성·합성 구조

각 모듈은 HCNT·VCNT 좌표를 공유하고, `background → mux_mole → mux → mux_start` 순서로 RGB를 전달합니다. 담당 영역에서는 해당 이미지의 RGB를 출력하고, 그 밖의 영역에서는 이전 모듈의 RGB를 유지합니다. 모듈 연결 순서에 따라 표시 우선순위가 정해지며, 마지막의 시작 화면이 최상위에 표시됩니다.
프로젝트에서는 ROM 주소에 사용하는 좌표의 하위 비트를 절삭해 이미지 표시 배율을 조정했습니다. 하위 2bit를 제외하면 4×4 픽셀이 동일한 ROM 주소를 참조해 원본 이미지를 4배 크기로 표시할 수 있습니다.

## 팀 전체 게임 동작과 개선

팀 프로젝트는 PS/2 키보드 입력에 따른 망치 이동·타격, LFSR 기반 두더지 등장과 3단계 진행을 포함합니다. ENTER를 유지할 때 반복 가산되는 문제는 ONHIT 카운터의 특정 값에서 한 Clock만 가산하도록 개선했고, 같은 등장 주기의 중복 득점은 다음 주기까지 재획득을 차단하도록 처리했습니다. 이 내용은 팀 전체의 구현 결과입니다.

## 결과

화면 좌표와 RGB 전달 규칙을 바탕으로 여러 화면 요소를 합성하고, 팀의 입력·게임 제어 모듈과 연결해 DE2 보드에서 게임 화면을 확인했습니다.

<details>
<summary>구현 코드</summary>

```verilog
assign HD1     = HCNT - 12'd100;         // 스프라이트 원점 기준 상대 좌표
assign ADD_M10 = {VD1[7:2], HD1[7:2]};   // 하위 2bit 제거 → 4×4 pixel이 같은 ROM 주소
```
```verilog
else if ((NONCNT == 30'd0) && (ONHIT == 30'd10))
    POINT <= POINT + 7'd10;   // 주기당 1회, ONHIT가 10을 지나가는 한 clock에서만 가산
```

</details>

<details>
<summary>팀 전체 게임 사양</summary>

| 조작 | W·A·S·D로 망치를 30 pixel씩 이동, ENTER로 타격, SPACE로 시작 및 스테이지 전환 |
| --- | --- |
| 점수 | 타격 성공 시 +10점, 100점 도달 시 다음 스테이지 |
| 스테이지 | 총 3단계, 단계마다 등장 주기 파라미터 SPEED가 120000 → 80000 → 40000으로 감소 |
| 두더지 | 3×3 구멍 9개에서 랜덤 등장, 4장의 스프라이트로 올라오고 내려가는 애니메이션 구성 |

</details>
