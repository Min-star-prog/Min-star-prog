- **좌표 복원:** 보정값을 이용한 mm 단위 3D 생성, 깊이·재투영 유효성 확인
- **목표값:** 전완 방향각·손목 Pitch/Roll·Gripper 계산

<details>
<summary>스테레오 보정과 3D 좌표 복원</summary>

좌우 영상에서 같은 관절·마커를 대응시키고 카메라 내부 파라미터, 왜곡 계수, 좌우 회전·이동 보정값을 사용해 3D 위치를 복원했습니다.

정렬된 스테레오의 기본 깊이 관계는 다음과 같습니다. f와 d는 픽셀, B와 Z는 같은 거리 단위를 사용합니다.

$$
Z \simeq \frac{fB}{d}, \qquad d=x_L-x_R
$$

실제 `stereo_geometry.c`는 보정된 두 관측 광선으로 위치를 계산하고, 퇴화한 광선·비정상 보정값·음의 깊이·큰 재투영 오차를 거부합니다. 단순 시차 식은 원리를 설명하는 식이며 실제 구현은 보정 기하를 사용합니다.

<details>
<summary>고정된 사람 기준축과 전완 목표각</summary>

팔꿈치 E에서 손목 W로 향하는 전완 벡터로 수평 방위각과 수직 고도각을 계산했습니다. 카메라가 사람을 마주 보는 배치에 맞춰 각도 계산에만 X·Z 방향을 반전합니다. 저장 위치의 원점이나 깊이 부호를 바꾸는 처리는 아닙니다.

$$
\mathbf f_{camera}=\mathbf W-\mathbf E, \qquad \mathbf f_{person}=(-f_x,f_y,-f_z)
$$

$$
\theta_{roll}=\frac{180}{\pi}\operatorname{atan2}(f_{person,x},f_{person,z})
$$

$$
\theta_{pitch}=\frac{180}{\pi}\operatorname{atan2}(f_{person,y},\sqrt{f_{person,x}^2+f_{person,z}^2})
$$

`Elbow Roll/Pitch`는 전완 방향을 전달하는 제어 채널 이름입니다. 해부학적인 팔꿈치 내각을 의미하지 않습니다. 최종 스테레오 경로에서는 어깨선으로 BodyFrame을 다시 만들거나 어깨 폭으로 실측 위치를 나누지 않습니다.

<details>
<summary>손목 Pitch·Roll과 Gripper 계산</summary>

**손목 Pitch:** 전완 방향과 손목에서 손가락 중점으로 향하는 손 방향 사이의 굽힘을 계산하고, 엄지→검지 축으로 부호를 결정했습니다.

**손목 Roll:** 전완 축을 중심으로 손 평면이 얼마나 회전했는지 고정 사람 기준축에서 계산했습니다. 기준 자세, 손 평면의 연속성, 각도 unwrap을 함께 처리했습니다.

**Gripper:** 같은 영상 안의 엄지·검지 간격을 손 크기와 비교해 개방 목표를 0(닫힘)\~1(열림)로 만들었습니다. 손목의 3D 계산 성공 여부와 갱신 조건을 분리했습니다.

- 한쪽 영상의 손목·엄지·검지가 모두 유효하면 그 영상으로 계산
- 필요한 점이 누락되면 완전한 반대쪽 영상 관측을 사용
- 손 크기와 간격 계산에서 좌우 영상의 픽셀을 혼합하지 않음
- 손가락 관측이 없거나 손 평면이 퇴화하면 마지막 유효 손목값 유지
- 최초 손목·그리퍼 관측 전에는 임의의 새 목표를 만들지 않음

`pose_hand.c`와 `forearm_mapping.c`에서 전완·손목·그리퍼의 상태와 갱신 조건을 구분했습니다.

</details>

## 입력 누락·유효 조건

- **관측 예외:** 손가락 누락 시 전완 계산 유지, 채널별 HOLD·invalid 조건 분리

<details>
<summary>좌표 필터·각도 연속성과 HOLD</summary>

작은 관측 오차가 손목 방향의 큰 변화로 이어지지 않도록 좌표와 각도 처리 단계를 나눴습니다. 제공 소스의 현행 경로는 픽셀/각도 EMA와 3D Kalman 설정을 사용하며, 개발 문서의 One Euro 실험 이력과 구분했습니다.

| 입력 조건 | 처리 |
| --- | --- |
| ±180° 경계 | unwrap으로 연속 회전이 큰 역방향 점프로 해석되지 않도록 처리 |
| 수직 전완 | 수평 방향의 관측성이 낮으면 마지막 관측 방위각 유지, 관측 가능 상태를 별도 관리 |
| 중복 프레임 | 같은 관측을 다시 필터링하거나 시간 aging하지 않고 HOLD |
| 팔꿈치·손목 검출 실패 | 기존 0.35초 HOLD 후 invalid 정책 적용 |
| 손가락만 누락 | 전완 목표는 계속 갱신하고 손목·그리퍼는 각자의 유효 조건에 따라 유지 |
| 팔 선택·단안/스테레오 경로 변경 | 이전 경로의 각도·손목 기준 이력을 초기화 |

이 처리는 목표값의 유효성과 연속성을 다루는 단계입니다. 로봇별 방향·영점·가동범위와 출력 제한은 다음 제어 모듈에서 적용합니다.

</details>

<details>
<summary>채널별 유효 조건·중복 입력·재생 경계</summary>

**채널별 처리:** 손가락이 없어도 팔꿈치·손목이 유효하면 전완 갱신은 유지합니다. 손목 평면의 퇴화나 손가락 누락은 마지막 손목 목표를 유지하고, Gripper는 같은 영상의 완전한 2D 관측이 있는지 별도로 검사합니다.

**중복·실패 처리:** frame\_id가 같은 입력은 새 프레임처럼 필터링하지 않습니다. 팔꿈치·손목 실패, 비정상 수치와 깊이는 새 목표로 승인하지 않고 HOLD·invalid 규칙에 따릅니다.

**통합 경계:** 사람 목표각과 로봇 보정·출력을 분리해 오류가 좌표 복원, 각도 기준, 로봇 방향 설정 중 어디에서 발생했는지 나눠 확인했습니다. 녹화·재생에서는 최종 명령 샘플이 중복 소비되거나 보정이 다시 적용되지 않도록 입력 경로를 구분했습니다.

**협업:** 팀원들과 원점·축·단위, valid 의미와 호출 시점을 맞추고 앞뒤 로직을 함께 검토했습니다. 담당 계산 함수뿐 아니라 다음 모듈이 결과를 사용하는 조건까지 확인하며 통합했습니다.

</details>

## UART·실행 주기 통합

- **통신:** 프레임·세션·유효 정보 전달, CRC·길이·범위 검사
- **실행 주기:** 새 관측에서 목표 갱신, 20 ms 제어 틱에서 추종·출력·기록

<details>
<summary>보드 간 UART 패킷과 PC 상태 응답</summary>

**보드 간 관측 패킷**

`stereo_uart_protocol.c`에서 170-byte 고정 길이 패킷의 인코딩과 바이트 단위 수신 파서를 구성했습니다. 세션·시퀀스·프레임 정보, 17개 관절의 좌표·score·valid, 4개 마커 및 메타데이터를 함께 전달합니다.

수신 바이트를 누적해 완성된 프레임의 형식·길이·CRC32·좌표 범위를 확인한 뒤 새 관측으로 전달합니다. 정상 수신·CRC 오류·형식 오류·범위 오류는 구분해 집계합니다.

| 통신 경로 | 용도·설정 |
| --- | --- |
| PS UART0 | 좌우 보드의 관측·제어 데이터 / 기본 115200 baud, 8N1 |
| PS UART1·USB 콘솔 | PC 명령·상태·관절 Telemetry / 일반 빌드 115200, TRACE 빌드 921600 baud |
| RIGHT / 로봇0 | 스테레오·사람 오른팔 목표 처리 및 로봇0 제어 |
| LEFT / 로봇1 | 관측 전달 및 전달받은 목표에 로봇1의 자체 보정 적용 |

**명령을 보낸 상태와 실제 보드 상태의 구분**

- `R`: 녹화 준비·종료 요청, `P`: 목록·재생 중지, `V`: 상태 조회
- `[REC_STATE]`의 ui/mode/pwm으로 준비·녹화·저장·재생 상태 확인
- 수신한 줄이 완성된 뒤 해석하고, 송신했다는 이유만으로 저장·재생 완료로 표시하지 않음
- 입력 중단·PWM 해제·녹화 메뉴 취소의 의미를 구분해 모니터·Unity 계약과 연결

관절 Telemetry는 엔코더로 읽은 실제 관절 위치가 아니라 제어 명령값 기준입니다.

</details>

<details>
<summary>관측 갱신과 20 ms 제어 틱의 통합</summary>

CNN 관측은 영상 처리 완료 시점에 갱신되므로 20 ms 서보 제어 틱과 같은 주기로 가정하지 않았습니다. `main.c`에서 CNN 서비스, UART 수신, 새 좌표·목표값 갱신과 제어 진행의 호출 순서를 맞췄습니다.

- 새 관측 경로: 관측 검증 → 스테레오 위치 → 사람 목표값 갱신
- 20 ms 제어 틱: 승인된 목표 추종 → 로봇별 보정·제약 → PWM 적용·모드별 기록/재생
- 관측이 잠시 끊겨도 마지막 승인 목표까지 진행하고 도착 후 명령 자세 유지
- 재생 경로는 저장된 최종 서보 명령을 사용하며 사람 각도 보정을 다시 적용하지 않음

**관측·사람 목표·로봇 제어·출력의 연결**

**연동한 로봇 보정·모션 제어 모듈**

[상세 그림 — Notion](https://app.notion.com/p/3f723ec941b7816881c9fe81751f1529#4b84fa947c2c4d8fb068d9cb2b49d594)

팀원 담당 모듈. scale·direction·offset과 가동범위·속도·가속도 제한, 순기구학 기반 자기충돌·테이블 충돌 검사에 개인 목표값 경로를 연결했습니다.

20 ms는 제어 틱의 설정값이며 카메라 인식 FPS나 사람 입력부터 로봇 반응까지의 전체 지연 측정값은 아닙니다.

## 문제 해결

- **현상:** 단안 상대 깊이·몸통 기준축 변화로 사람과 로봇의 회전 방향 불일치
- **전환:** 스테레오 3D 좌표와 고정 기준축 적용, 좌표 복원·각도 계산·로봇 보정 경계 분리

<details>
<summary>상대 Z·몸통 기준축 문제와 스테레오 전환</summary>

**현상:** 사람이 팔을 왼쪽으로 회전했지만 로봇이 오른쪽으로 움직이는 문제가 발생했습니다.

**원인 분석:** 초기 단안 방식은 어깨 폭과 인체 비율로 상대 깊이를 재구성했습니다. 같은 2D 관측에서 깊이가 다른 후보가 존재했고, 손가락처럼 짧은 거리에서는 작은 깊이 오차가 손목 각도에 크게 반영됐습니다. 또한 양어깨로 만든 BodyFrame이 몸통과 함께 회전해 전완의 상대 회전각이 축소·왜곡·역전될 수 있었습니다.

**단안 상대 깊이 오차와 로봇 동작 불일치**

[상세 그림 — Notion](https://app.notion.com/p/3f723ec941b7816881c9fe81751f1529#0abb6199dbf545e3b993f52c5ff19b09)

단안 입력의 깊이 모호성은 출력 보정만으로 해소하기 어려워 입력 좌표계를 전환했습니다.

**몸통 기준축 회전에 따른 상대각 변화**

[상세 그림 — Notion](https://app.notion.com/p/3f723ec941b7816881c9fe81751f1529#9e01d974ea4440dea054ea87b8285af0)

제본 자료의 개발 당시 화면. 기준축이 팔과 같은 방향으로 움직이면 상대각의 해석이 달라지는 과정을 보여줍니다.

**수정:** 좌우 보정 카메라의 관측으로 고정 원점의 3D 좌표를 복원했습니다. 이후 어깨선 기반 좌표축 대신 사람의 오른쪽·위쪽·전방에 맞춘 고정 축에서 전완 각도를 계산했습니다.
